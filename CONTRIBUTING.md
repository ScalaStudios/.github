# Contributing

Scala Studios takes issues and pull requests on its public repositories.

If the project you want to change has its own `CONTRIBUTING.md`, follow that. It overrides this file.

## Halo

Read [Halo's contributing guide](https://github.com/ScalaStudios/Halo/blob/main/CONTRIBUTING.md). Open an issue before a large change: a new feature, a new dependency, a schema change, an API change, or a change to how people sign in. Small, contained fixes can go straight to a pull request.

## Shipyard

Keep the change focused. Include a test for non-trivial logic. Run `go test ./...` and the UI build before opening a pull request. The same notes are in the [Shipyard README](https://github.com/ScalaStudios/Shipyard#contributing).

## Security

A vulnerability does not belong in a public issue or pull request. Follow [SECURITY.md](SECURITY.md).
