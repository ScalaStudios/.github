# Security policy

Report vulnerabilities in the repository they affect. Do not open a public issue, pull request, or discussion for a security problem.

## Halo

Halo is an identity provider. Report vulnerabilities through [GitHub private vulnerability reporting](https://github.com/ScalaStudios/Halo/security/advisories/new).

What to include, which versions are supported, and the maintainers' response targets are in [Halo's security policy](https://github.com/ScalaStudios/Halo/blob/main/SECURITY.md). Until 1.0, only the latest commit on `main` receives fixes.

## Shipyard

Do not open a public issue. Report the vulnerability privately to the maintainers, and leave a reasonable window for a fix before disclosure. See the [security section](https://github.com/ScalaStudios/Shipyard#security) of the Shipyard README.

## Any other repository

If that repository has a `SECURITY.md`, follow it. If it does not, open a [private security advisory](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability) on the repository rather than a public issue.
